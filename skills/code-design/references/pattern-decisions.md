# 模式决策：问题先于名称

## 采用门槛

确认实际问题：变化维度、重复决策、接口不兼容、生命周期或协作复杂度。比较直接代码、现有抽象和候选模式。收益足以抵消新增间接调用、概念与测试成本时才采用。

没有模式也可以是优秀设计；不要求消除全部条件判断、使用全部原则或实现 GoF 类图。

## 创建型

| 模式 | 值得采用的信号 | 最简单替代/不宜采用时 | 核查点 |
|---|---|---|---|
| 工厂方法 | 创建策略需由不同提供者/子类定制 | 普通构造或工厂函数已足够 | 产品契约、失败、资源所有权；按参数分支通常是简单工厂 |
| 抽象工厂 | 多个产品必须成套兼容 | 只有一个产品或不要求配套 | 产品兼容性，新增产品族与产品种类的不同成本 |
| 建造者 | 构建有分步过程、组合约束或复杂配置 | 命名参数、配置对象即可 | 必填项、非法组合、可变性，不能泄漏半成品 |
| 原型 | 复制既有对象更符合创建需求 | 普通构造、不可变 copy 操作 | 深浅复制、引用共享、句柄能否复制 |
| 单例 | 明确范围内必须唯一，生命周期可说明 | 注入共享实例；无需全局唯一 | 并发初始化、测试隔离；不能保证跨进程唯一 |

## 结构型

| 模式 | 值得采用的信号 | 最简单替代/不宜采用时 | 核查点 |
|---|---|---|---|
| 适配器 | 外部/旧接口与调用方接口不同 | 直接调用或局部转换 | 错误、单位、空值、取消等语义转换 |
| 桥接 | 两个独立变化维度组合导致类型膨胀 | 单维度用策略或直接实现 | 维度独立性、组合约束 |
| 组合 | 树的叶子和分组需要统一操作 | 普通树遍历、简单集合 | 叶子不支持的操作、环、递归深度 |
| 装饰器 | 附加能力可独立组合叠加 | 包装函数或原生中间件 | 顺序、重复执行、异常与释放 |
| 外观 | 调用方反复协调复杂子系统 | 一个普通服务入口即可 | 不成长为吞下所有业务的巨型服务 |
| 享元 | 大量对象共享不可变部分，有内存证据 | 不可变数据共享或普通对象 | 内外部状态分离、缓存生命周期；先测量 |
| 代理 | 访问控制、延迟加载或远程访问需统一入口 | 显式服务调用、普通包装 | 不错误隐藏成本、失败与副作用 |

适配器改变接口契约，装饰器叠加能力，代理控制访问，外观简化入口。实现形状可能相似，按意图区分。

## 行为型

| 模式 | 值得采用的信号 | 最简单替代/不宜采用时 | 核查点 |
|---|---|---|---|
| 策略 | 同一目标有多种可替换算法/政策 | 函数参数、局部分支 | 共同契约，选择规则有明确归属 |
| 观察者 | 变化需通知多个独立订阅方 | 回调、现有响应式机制 | 释放、重入、顺序、反馈循环；通知不等于可靠交付 |
| 状态 | 行为随状态变化，多处判断导致非法转换 | 枚举加转换函数 | 不变量、转换表、取消与终态；不必每态一个类 |
| 责任链 | 处理者可组合，有继续/中止/接管规则 | 简单固定顺序调用 | 顺序、短路、未处理、错误传播、副作用次数 |
| 命令 | 操作需排队、记录、延迟执行或撤销 | 函数/闭包 | 执行身份、幂等、撤销可行性；副作用未必可撤销 |
| 模板方法 | 稳定骨架需要少量受控覆写 | 函数组合或策略 | 子类契约、钩子顺序、脆弱继承 |
| 迭代器 | 统一遍历而不暴露内部结构 | 内置迭代器/生成器 | 遍历期间修改、释放、惰性/无限序列 |
| 中介者 | 多对象协调形成复杂依赖网 | 局部协调函数/控制器 | 只承担协调，不吞入所有业务细节 |
| 备忘录 | 需恢复历史状态并保持封装 | 不可变快照/版本记录 | 大小、版本、敏感数据；不能撤销外部副作用 |
| 访问者 | 对象结构稳定，遍历操作反复新增 | 遍历、模式匹配 | 新增对象种类成本、类型穷尽性 |
| 解释器 | 简单受控的小型语法需要执行 | 现有解析器、直接谓词 | 优先级、错误输入、资源限制；复杂语言不用手造系统 |

策略通常由调用方选采用哪种做法；状态由当前状态和转换规则决定此刻怎样响应。异步复杂性不能单靠换成状态类解决。

## 常见架构与实践

- **MVC/MVP/MVVM**：界面组织方式。明确界面、交互状态和业务边界；采用名称不保证职责正确，不强制全项目迁移。
- **Clean/Hexagonal Architecture**：在需要时保护业务与外部系统之间的边界。层数由复杂度决定，不提供价值的层可以合并。
- **Repository**：提供有意义的数据访问契约。不机械复制 API/数据库方法；明确缓存、事务与一致性责任。
- **依赖注入**：在组合入口提供依赖及生命周期。优先项目已有办法，构造注入也可以，容器非必需。
- **Event Bus**：跨模块解耦有收益时才用。命名、来源、订阅生命周期及交付语义清楚，不隐藏关键调用链。

这些不等同于 GoF 模式，不作为评分指标。

## 表达模式选择

合格：“新增导出算法，现在需改三处类型判断。把算法封装成可替换函数，由保存流程统一选择，采用策略思想。无需注册框架；代价是多一个选择入口。若只保留一种算法，可收回直接调用。”

不合格：“为了符合开闭原则，所有类增加接口。”缺少真实变化方向、收益和契约。
